# Opportunity tree and prioritisation assumptions

```
Outcome: more new users reach durable, paid-for repeat value
├── Opportunity A: first session lacks a concrete next action  ← chosen
│   ├── Solution A1: job-led first session → note lines become tasks (this prototype)
│   └── Solution A2: meeting template preselected (template already exists; sequencing only)
├── Opportunity B: users do not rediscover saved notes
│   └── B1: revisit cue naming open tasks (part of A1, simulated)
├── Opportunity C: price/plan presentation
│   └── C1: pricing tests (deprioritised: does not create repeat value)
└── Opportunity D: acquisition campaigns
    └── D1: channel optimisation (deprioritised: changes mix, which can fake a lift)
```

## Why A1 first (assumptions, no invented scores)
- It is bounded and testable in one session. It produces a tangible user flow and measurable learning.
- It reuses existing features, so the build risk is in sequencing and instrumentation, not new systems.
- Reach and impact are **unknown**. No RICE score is given because the inputs would be invented.
- Acquisition-mix and refund guardrails keep the decision commercially honest.
